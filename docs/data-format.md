# Данные и результат поиска

Проект находит статьи базы знаний по вопросам пользователей. Ранжированный
список документов можно передать в RAG-пайплайн для подготовки ответа.
Один вопрос может требовать нескольких статей: например, инструкции и правил
использования сервиса.

## Входные данные

Файлы находятся в `data/` и хранят таблицы в формате Apache Arrow IPC,
совместимом с Feather. Для чтения в проекте используется
`retrieval.io.read_dataframe`.

### `articles.f`

База статей справки:

| Колонка | Содержимое |
|---|---|
| `article_id` | Целочисленный идентификатор статьи |
| `title` | Заголовок статьи |
| `body` | Исходный HTML статьи |

HTML может содержать таблицы, вкладки, спойлеры, ссылки и служебную разметку.
Модуль `preprocessing/` преобразует статьи в типизированные текстовые блоки,
сохраняя структуру разделов.

### `calibration.f`

Размеченные запросы для подбора параметров и оценки качества:

| Колонка | Содержимое |
|---|---|
| `query_id` | Идентификатор запроса |
| `query_text` | Текст вопроса пользователя |
| `ground_truth` | Релевантные `article_id`, разделённые пробелами |

Разметка используется в grouped nested 5-fold OOF-оценке. Нормализованные
дубли запросов попадают в один fold; параметры подбираются без использования
разметки внешнего проверочного fold.

### `test.f`

Запросы для запуска поиска:

| Колонка | Содержимое |
|---|---|
| `query_id` | Идентификатор запроса |
| `query_text` | Текст вопроса пользователя |

Для этого набора релевантные статьи не размечены. Сохранённые результаты
поисковых моделей позволяют сформировать ранжирование офлайн.

## `answer.csv`

Команда `python generate_answer.py` создаёт CSV с колонками:

| Колонка | Содержимое |
|---|---|
| `query_id` | Идентификатор из `data/test.f` |
| `answer` | Десять `article_id`, разделённых пробелами, в порядке релевантности |

Каждый запрос представлен ровно одной строкой. Идентификаторы внутри строки
уникальны и существуют в `articles.f`. Первая статья считается наиболее
релевантной. Проверки формата и полноты выполняются в `submission.py`.

## Метрики

Основная метрика — `MAP@10`: среднее значение average precision для первых
десяти документов. Дополнительно рассчитывается `Recall@K`, который показывает,
какая доля релевантных статей найдена среди первых K результатов.

Результаты оценки и метрики по отдельным folds находятся в `metrics/`.
Воспроизведение оценки описано в [README](../README.md).
